[ 13. 성능 최적화 이력 (Performance Optimization) ]
================================================================

적용일: 2026-05-13
대상: 전체 HTML 514개 파일 + css/style.css + images/로고.*


────────────────────────────────────────────────────────────────
문제 1 — 렌더링 차단 리소스 (FCP/LCP 저하)
────────────────────────────────────────────────────────────────

브라우저는 HTML을 그리기 전에 CSS와 폰트를 먼저 모두 받아야 합니다.
이 파일들이 "차단 리소스"로 작동하면 페이지가 늦게 보이기 시작합니다.

  개선 전:
    <link href="https://fonts.googleapis.com/.." rel="stylesheet">
    → 구글 폰트 910ms 동안 페이지 렌더링 완전 차단

    <link rel="stylesheet" href="/css/style.css">
    → style.css 190ms 동안 렌더링 차단

  개선 후 — 구글 폰트 비동기 로드:
    <link rel="preload" as="style" href="https://fonts.googleapis.com/..">
    <link rel="stylesheet" href="https://fonts.googleapis.com/.." media="print" onload="this.media='all'">
    <noscript><link rel="stylesheet" href="https://fonts.googleapis.com/.."></noscript>
    → media="print"으로 차단 없이 백그라운드 로드, 완료 후 적용

  개선 후 — CSS preload:
    <link rel="preload" href="/css/style.css" as="style" onload="this.onload=null;this.rel='stylesheet'">
    <noscript><link rel="stylesheet" href="/css/style.css"></noscript>

  효과: FCP 약 1초 이상 단축 기대


────────────────────────────────────────────────────────────────
문제 2 — LCP 이미지 늦게 로드 (Largest Contentful Paint 저하)
────────────────────────────────────────────────────────────────

LCP는 화면에서 가장 큰 요소(보통 히어로 이미지)가 보이는 시점입니다.
브라우저가 이 이미지를 "중요하다"고 인식하지 못하면 늦게 불러옵니다.

  개선 전:
    <img src="...cloudinary..." class="hero-img">
    → 브라우저가 다른 리소스보다 낮은 우선순위로 로드

  개선 후:
    <img src="...cloudinary..." class="hero-img" fetchpriority="high">
    → 브라우저에게 "이 이미지 최우선으로 받아라" 명시

  추가 개선 — Cloudinary 이미지 크기 최적화:
    개선 전 URL: /upload/l_text:...
    개선 후 URL: /upload/w_800,q_auto,f_auto/l_text:...
    → 히어로 이미지: 1024px → 800px, 자동 품질·포맷 최적화
    → 학원카드 이미지: /upload/w_740,h_400,c_fill,q_auto,f_auto/l_text:...
       (너비 740, 높이 400 고정 크롭, 자동 품질·포맷)

  효과: 이미지 용량 50~70% 감소, LCP 단축


────────────────────────────────────────────────────────────────
문제 3 — 화면 밖 이미지 선불 로드 (초기 로딩 낭비)
────────────────────────────────────────────────────────────────

학원카드 16개의 이미지는 스크롤해야 보이는 영역에 있습니다.
처음 접속 시 이 이미지들까지 모두 받으면 불필요한 네트워크 낭비입니다.

  개선 후:
    <img ... class="academy-card-img" loading="lazy">
    → 스크롤해서 화면 근처에 올 때만 이미지 다운로드
    → 히어로 이미지(첫 화면)는 lazy 없이 즉시 로드 유지


────────────────────────────────────────────────────────────────
문제 4 — CLS 레이아웃 이동 (Cumulative Layout Shift 저하)
────────────────────────────────────────────────────────────────

CLS는 페이지 로드 중에 요소들이 갑자기 위치가 바뀌는 현상입니다.
이미지에 크기 정보가 없으면 브라우저가 공간을 예약 못 해서 발생합니다.

  원인별 수정:

  ① 히어로 이미지 — CSS aspect-ratio 추가
    .hero-img { aspect-ratio: 1 / 1; }
    → 이미지 로드 전에 1:1 비율로 공간 미리 확보
    → 이미지 로드 후 레이아웃 이동 없음

  ② 로고 이미지 — HTML 속성 + CSS width 명시
    HTML: <img ... width="72" height="72">
    CSS:  .logo-img { width: 36px; height: 36px; }
    → 브라우저가 렌더링 전부터 정확한 크기 인식

  ③ 학원카드 이미지 — HTML 속성 추가
    <img ... width="740" height="400">
    → Cloudinary에서 w_740,h_400,c_fill로 항상 이 크기로 전달됨
    → 실제 크기와 HTML 속성이 일치 → 레이아웃 이동 없음

  효과: CLS 0.655 → 0.1 이하 개선 목표


────────────────────────────────────────────────────────────────
문제 5 — 로고 이미지 파일 크기 (불필요한 용량)
────────────────────────────────────────────────────────────────

  개선 전: 로고.webp 1024×1024 (32KB), 로고.jpg 1024×1024 (106KB)
  CSS 표시 크기: 36×36px → 원본이 28배 이상 과잉

  개선 후: 72×72로 리사이즈 (2x DPR 대응)
    로고.webp → 1.5KB (95% 감소)
    로고.jpg  → 2.3KB (98% 감소)
  원본 백업: images/로고_원본.webp, images/로고_원본.jpg

  주의: 로고 디자인 수정 시 원본 파일 사용 후 다시 72×72로 리사이즈할 것
